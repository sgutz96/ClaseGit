01 · Punto de partida

¿Qué problema estamos resolviendo?

Antes de escribir comandos, entiende por qué existe el control de versiones.

📁 El proyecto crece

Hay cambios, archivos nuevos, versiones y personas trabajando. Copiar carpetas como “final-final-ahora-si” no escala.

🕒 Necesitamos historial

Queremos saber qué cambió, cuándo cambió y quién hizo el cambio.

🤝 Necesitamos colaborar

Git permite versionar. GitHub añade una plataforma para compartir, revisar y colaborar.

🎯 MINI RETO

Crea tu proyecto de clase

Crea una carpeta llamada mi-primer-repositorio con un archivo index.html que muestre tu nombre, una breve descripción y una lista de 3 tecnologías que quieres aprender.

Inicializar

1
Entra a la carpeta
cd mi-primer-repositorio
2
Inicializa Git

Observa lo que ocurre

git status

Git te dirá qué archivos están sin seguimiento, modificados o listos para commit.

💡 Haz git status constantemente. Es tu tablero de control.
🧪 EJERCICIO

Primer checkpoint

Ejecuta git init, luego git status. Explica a un compañero qué significa que index.html aparezca como “untracked”.

03 · Plataforma

Git ≠ GitHub

Git funciona localmente. GitHub es un servicio donde puedes alojar repositorios Git y trabajar con otras personas.

Git

  • Control de versiones.
  • Funciona en tu equipo.
  • Registra commits y ramas.
  • No necesita internet para crear commits.

GitHub

  • Alojamiento remoto.
  • Colaboración y Pull Requests.
  • Issues y proyectos.
  • Automatización y opciones de publicación.

Otras opciones

GitHubColaboración y ecosistema.
GitLabRepositorios y DevOps.
BitbucketIntegración con Atlassian.
CodebergAlternativa comunitaria.

04 · Versionar

Tu primer commit

El commit es una fotografía identificable de un estado del proyecto.

1
Revisa
git status
2
Prepara los archivos
git add .
3
Crea el checkpoint
git commit -m "feat: estructura inicial"
4
Mira el historial
git log --oneline

¿Qué hace git add?

Mueve cambios seleccionados hacia el área de preparación. No crea todavía el commit.

¿Qué hace git commit?

Guarda un punto de control en el repositorio local con un mensaje que explica el cambio.

🧪 EJERCICIO

Haz dos versiones

Después del primer commit, modifica el título de tu index.html, vuelve a ejecutar git status, git diff, git add . y crea un segundo commit.

05 · Remoto

Conecta tu proyecto con GitHub

Ahora tu historial local tendrá un destino remoto.

1
Crea un repositorio vacío en GitHub

Usa un nombre como mi-primer-repositorio. Para esta práctica, evita agregar archivos automáticamente si ya tienes el proyecto local.

2
Configura la rama principal
git branch -M main
3
Agrega el remoto
git remote add origin URL_DEL_REPOSITORIO
4
Sube la rama
git push -u origin main
⚠️ Importante: nunca pegues contraseñas, API keys, tokens o secretos dentro del repositorio. Aprende a usar .gitignore desde el primer proyecto.

Tu primer .gitignore

node_modules/
.env
dist/
.vscode/
*.log
🚀 RETO

Tu primer repositorio público

Sube tu proyecto, agrega un README.md con descripción, tecnologías, instalación y uso. Después comparte el enlace con el profesor.

06 · Colaboración

Branches + Pull Requests

Las ramas permiten desarrollar cambios sin alterar directamente la rama principal.

Crear una rama

git branch desarrollo
git switch desarrollo

También puedes crear y cambiar en una sola operación:

git switch -c desarrollo

Publicar la rama

git push -u origin desarrollo

Luego puedes abrir un Pull Request en GitHub para revisar el cambio antes de integrarlo.

Flujo de equipo

main
←
feature / desarrollo
→
Pull Request
→
Review → Merge

Simulen un equipo

Persona A crea una rama y cambia el contenido de index.html. Persona B revisa el Pull Request. Escriban al menos un comentario y decidan si el cambio puede integrarse.

07 · Situaciones reales

¿Qué pasa cuando hay un conflicto?

Un conflicto no significa que Git “se dañó”. Significa que necesita ayuda humana para decidir qué versión conservar.

1
Actualiza tu información
git pull
2
Si Git marca un conflicto, abre el archivo

Encontrarás marcadores como <<<<<<<, ======= y >>>>>>>.

3
Decide qué contenido queda

Edita manualmente el archivo y elimina los marcadores.

4
Registra la resolución
git add .
git commit -m "fix: resuelve conflicto"
💥 EJERCICIO CONTROLADO

Provoca un conflicto

Dos estudiantes modifican intencionalmente la misma línea desde ramas diferentes. Intenten integrarlas y resuelvan el conflicto juntos. El objetivo no es evitar el conflicto: es aprender a leerlo.

Idea clave: git pull trae cambios e intenta integrarlos. git fetch actualiza la información remota sin integrar automáticamente esos cambios.
08 · Proyecto final

De repositorio a producto

GitHub puede ser mucho más que “un lugar donde subir código”. Puede convertirse en parte de tu flujo de trabajo.

📄 README

Explica qué es el proyecto, cómo instalarlo, cómo usarlo y quién lo construyó.

🐛 Issues

Registra tareas, errores, mejoras o ideas de trabajo.

⚙️ Actions

Permite automatizar tareas como pruebas, validaciones o despliegues.

Deploy: el último paso

Una vez que tu código está en GitHub, puedes conectarlo a servicios de despliegue compatibles con tu proyecto. La idea pedagógica es: código → repositorio → build → publicación.
