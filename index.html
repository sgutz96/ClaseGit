01 · Punto de partida

¿Qué problema estamos resolviendo?

Antes de escribir comandos, entiende por qué existe el control de versiones.

03 · Plataforma

Git ≠ GitHub

Git funciona localmente. GitHub es un servicio donde puedes alojar repositorios Git y trabajar con otras personas.

Git

  • Control de versiones.
  • Funciona en tu equipo.
  • Registra commits y ramas.
  • No necesita internet para crear commits.

GitHub

  • Alojamiento remoto.
  • Colaboración y Pull Requests.
  • Issues y proyectos.
  • Automatización y opciones de publicación.

Otras opciones

GitHubColaboración y ecosistema.
GitLabRepositorios y DevOps.
BitbucketIntegración con Atlassian.
CodebergAlternativa comunitaria.

07 · Situaciones reales

¿Qué pasa cuando hay un conflicto?

Un conflicto no significa que Git “se dañó”. Significa que necesita ayuda humana para decidir qué versión conservar.

1
Actualiza tu información
git pull
git pull
  1. Haz clic en el botón de sincronización (flechas circulares) en la barra inferior de VS Code, o en ... → Pull.
2
Si Git marca un conflicto, abre el archivo

Encontrarás marcadores como <<<<<<<, ======= y >>>>>>>. En VS Code, el archivo aparece resaltado en rojo dentro de Control de código fuente.

3
Decide qué contenido queda

Edita manualmente el archivo y elimina los marcadores, o usa los botones Accept Current Change, Accept Incoming Change o Accept Both Changes que VS Code muestra sobre el conflicto.

4
Registra la resolución
git add .\ngit commit -m "fix: resuelve conflicto"
git add .\ngit commit -m "fix: resuelve conflicto"
  1. Marca el archivo como resuelto (+) y haz clic en ✓ Commit, igual que un commit normal.
💥 EJERCICIO CONTROLADO

Provoca un conflicto

Dos estudiantes modifican intencionalmente la misma línea desde ramas diferentes. Intenten integrarlas y resuelvan el conflicto juntos. El objetivo no es evitar el conflicto: es aprender a leerlo.

Idea clave: git pull trae cambios e intenta integrarlos. git fetch actualiza la información remota sin integrar automáticamente esos cambios.

🌐 GitHub Pages: publica tu sitio

GitHub Pages permite convertir un repositorio en un sitio web estático publicado. Es especialmente útil para proyectos HTML, CSS y JavaScript.

1

El repositorio debe contener el sitio, normalmente con un index.html como punto de entrada.

2
Abre Settings → Pages

En GitHub, entra a la configuración del repositorio y busca la sección Pages.

3
Selecciona la fuente

Selecciona la rama y la carpeta desde la que GitHub Pages tomará los archivos.

4
Visita la URL

GitHub generará una dirección pública para tu proyecto. En un sitio de proyecto normalmente tendrá la forma usuario.github.io/nombre-repositorio.

Concepto clave: GitHub Pages no reemplaza a Git. Git versiona tu proyecto; GitHub almacena el repositorio; GitHub Pages publica una versión web de ese contenido.

09 · Herramientas

¿Dónde puedo ejecutar Git?

Git es el sistema de control de versiones. Terminal, PowerShell, Git Bash y GitHub Desktop son distintas formas de interactuar con Git.

🖥️ Terminal de Windows

Windows Terminal es la aplicación que abre diferentes intérpretes de comandos. Puede trabajar con PowerShell, Command Prompt y otros shells.

Idea: Terminal es el contenedor/interfaz; PowerShell es uno de los intérpretes que puedes ejecutar dentro de ella.

cd mi-primer-repositorio
git status
git add .
git commit -m "feat: primer cambio"
git push

🔷 PowerShell

PowerShell es un shell y lenguaje de automatización de Microsoft. En Windows es una opción habitual para trabajar con Git desde comandos.

Idea: escribes comandos Git igual que en otros shells; lo que cambia principalmente es el shell que interpreta los comandos del sistema.

Get-Location
Set-Location .\mi-primer-repositorio
git status
git log --oneline

🐧 Git Bash

Git Bash, incluido con Git for Windows, ofrece un entorno de shell con comandos de estilo Unix junto con Git.

Idea: es muy útil si quieres aprender comandos como ls, pwd, mkdir y combinarlos con Git.

pwd
ls
cd mi-primer-repositorio
git status
git add .
git commit -m "feat: cambio"

🖱️ Visual (sin terminal)

En algunos computadores o salas de clase la terminal está bloqueada por políticas de seguridad. En ese caso puedes hacer exactamente el mismo trabajo desde la interfaz gráfica.

Idea: VS Code (panel Control de código fuente) y GitHub Desktop hacen las mismas acciones que git status, git add, git commit y git push, con clics en vez de comandos.

💡 Si un aula tiene la terminal restringida, usa VS Code o GitHub Desktop: ningún ejercicio de esta clase requiere obligatoriamente escribir comandos.

📊 Comparación rápida

TerminalAplicación donde abres shells.
PowerShellShell de Windows para comandos y automatización.
Git BashShell estilo Unix incluido con Git for Windows.
GitHub DesktopInterfaz gráfica para trabajar con Git.
Regla: los comandos git status, git add, git commit, git pull y git push son comandos de Git. No son comandos exclusivos de PowerShell, Terminal o Git Bash.
10 · Distintas terminales

Crear un repositorio desde cada terminal

Antes de hablar de Git, cada terminal tiene su propia forma de crear carpetas y moverte entre ellas. Los comandos de Git son siempre los mismos; lo que cambia es el shell.

🖥️ CMD (Simbolo del sistema)

El interprete clasico de Windows.

mkdir mi-primer-repositorio
cd mi-primer-repositorio
git init

🔷 PowerShell

Shell de Microsoft, mas moderno que CMD.

New-Item -ItemType Directory mi-primer-repositorio
Set-Location mi-primer-repositorio
git init

💡 mkdir tambien funciona en PowerShell: es un alias de New-Item.

🐧 Git Bash

Shell estilo Unix incluido con Git for Windows.

mkdir mi-primer-repositorio
cd mi-primer-repositorio
git init

🍎 Terminal (macOS / Linux)

Mismo estilo de comandos que Git Bash, de forma nativa.

mkdir mi-primer-repositorio
cd mi-primer-repositorio
git init

🖱️ Visual (VS Code)

Si no puedes o no quieres usar la terminal, todo el proceso se hace con clics.

  1. Crea la carpeta desde el explorador de archivos del sistema.
  2. Archivo → Abrir carpeta... en VS Code.
  3. Panel Control de código fuente → Initialize Repository.
Idea clave: git init, git status, git add y git commit son comandos de Git y se escriben igual en cualquier terminal. Lo unico que cambia entre CMD, PowerShell, Git Bash o una terminal de macOS/Linux es como creas carpetas y te mueves entre ellas.

📊 Equivalencias rapidas

Crear carpetaCMD/Git Bash/macOS: mkdir · PowerShell: New-Item -ItemType Directory
Entrar a carpetaTodas: cd · PowerShell tambien: Set-Location
Ver contenidoCMD: dir · PowerShell: Get-ChildItem (o ls) · Git Bash/macOS: ls
Iniciar GitIdentico en todas: git init

📄 Que es el README y por que importa?

El README.md es el primer archivo que GitHub muestra al entrar a un repositorio. Es la carta de presentacion del proyecto: explica que es, para que sirve y como usarlo, antes de que alguien revise una sola linea de codigo.

Un buen README ayuda a que:

  • Otra persona (o tu mismo en 6 meses) entienda el proyecto sin tener que preguntarte.
  • Un reclutador o companero de equipo confie en que el proyecto esta bien documentado.
  • Cualquiera pueda instalar y ejecutar el proyecto siguiendo pasos claros.

12 · Interfaz gráfica

¿Cómo funciona GitHub Desktop?

GitHub Desktop permite trabajar con muchos comandos y flujos de Git mediante una interfaz visual, sin escribirlos todos en la terminal.

1. Iniciar sesión

Instala GitHub Desktop e inicia sesión con tu cuenta de GitHub para conectar el cliente con tus repositorios remotos.

2. Crear o clonar

Puedes crear un repositorio nuevo, agregar uno local existente o clonar un repositorio desde GitHub.

3. Editar en VS Code

Abre el proyecto en tu editor y modifica los archivos normalmente.

4. Revisar cambios

GitHub Desktop muestra visualmente los archivos modificados y los cambios realizados.

5. Commit

Escribes el mensaje del commit y confirmas los cambios desde la interfaz.

6. Push / Pull

Publicas tus commits en GitHub con Push y recuperas cambios remotos con Pull.
